## Непереговорные ограничения

1. **Сайт исключительно информационно-справочный:** никакой подачи заявлений, архивных запросов, платных услуг, заказов или платежей.
2. Нельзя придумывать даты, архивные шифры, названия фондов, адреса, телефоны, e-mail, ссылки или содержание PDF. Если в источнике нет поля — отображать «Не указано»/не показывать и отмечать для редактора.
3. Не публиковать документы из комплаенс-архива, пока не выполнена ручная/редакторская проверка разрешённости публикации, персональных данных и режима доступа. Для демо можно подготовить закрытые записи/список с `needsReview` и `published:false`, но **не отдавать закрытые бинарные файлы через публичный URL**.
4. Публичный AI работает только с опубликованными, разрешёнными метаданными. Проверка полномочий на сервере, подтверждённые citations, защита от prompt injection, лимит запросов, timeout, max tokens. Никаких прав администратора у AI.
5. Не читать и не выводить значения секретов из `.env.local`, не коммитить `.env*`, `.data`, ключи, приватные материалы; никогда не отправлять персональные документы в OpenRouter.
6. Не запускать миграции Supabase без явного разрешения; существующую схему не стирать. Не делать платных API-вызовов. Не трогать production.
7. Не делать git commit/push/deploy без явного подтверждения. Учитывать существующие незакоммиченные изменения.

## Работа по приоритету

### P0. Завершить и проверить AI и безопасность демо
- Изучить существующий AI-код и handoff. Довести обработку RU/KZ/EN, ошибки ключа/лимита и безопасную деградацию.
- Убедиться, что OpenRouter вызывается ТОЛЬКО на сервере, ключ не попадает в JS клиента, bundle, логи, исходники и ответы.
- Системный промпт не заменяет серверные проверки доступа и ссылок.
- Предусмотреть режим `DEMO_READ_ONLY=true`, при котором публичные изменения данных выключены, но информационные разделы, поиск и AI доступны. Если невозможно реализовать без нарушения существующей архитектуры — чётко задокументировать ограничение.
- Настроить переменные окружения для Vercel через `.env.example` БЕЗ реальных значений; URL `.vercel.app` определяется после первого деплоя. Учитывать строгую проверку APP_ORIGIN и site URL.

### P1. Контакты филиалов
- Извлечь фактические строки из .xls; привести в валидированную типизированную структуру с отдельным `source` и `needsReview`.
- Подключить к `/branches` и существующей карте. Маркеры ставить только при проверенных геоданных. Кнопки маршрута создавать по фактическому адресу, корректно URL-encode; не выдумывать координаты, режим работы или фото.
- Добавить поиск по городу/названию, карточки, адаптивность; не сломать редакторский интерфейс.

### P2. Хронология 2026
- Извлечь RU/KZ событийные записи из двух частей .docx. Сохранять исходную формулировку и дату, `sourceDocument`, `year`, `month`, `day?`, `language`, `needsReview`, `reviewNotes`.
- Обнаружить и явно отметить несовпадения между языковыми версиями; **не исправлять молча**. Пример: событие о телефонной станции 1946 года содержит разные юбилейные числа в RU/KZ.
- Добавить интерактивную доступную хронологию (месяц/год/тематика, RU/KZ, EN fallback с пометкой, что перевод недоступен). Ссылки на архивные документы показывать только если существуют реальные опубликованные записи.
- Придерживаться визуальной системы ALTAI ARCHIVE: editorial heritage, Swiss typography, Altai identity, high contrast и читаемость для 50+.

### P3. Комплаенс-раздел
- Инвентаризировать 7z: список реальных имён и типов документов, языки, размеры, потенциально чувствительные материалы. Сформировать `docs/COMPLIANCE_CONTENT_REVIEW.md`.
- Не публиковать файлы до разрешения и проверки; если есть безопасно публикуемые метаданные, показывать только проверенный публичный список.

### P4. Подготовка Vercel и GitHub
- Подготовить `docs/VERCEL_DEPLOY_CHECKLIST.md` с конкретной схемой для этого репозитория, инструкциями установки env, read-only особенностями файловой системы Vercel, проверки HTTPS, мобильного UI, отсутствия секретов и сохранности данных. Учесть что локальное JSON-хранилище не является постоянной production-БД и upload не будет персистентным в Vercel.
- Не создавать иллюзию полноценно работающей админки на Vercel, если persistence не решена.
- Для демонстрации предусмотреть защиту от неожиданных AI расходов: provider-side spending limit на собственном ключе, запросы по IP+общий лимит с общим store (не in-memory на Vercel), ограничение входного текста и output tokens, fallback при 429. Не рассчитывать на бесплатный тариф как на SLA.
