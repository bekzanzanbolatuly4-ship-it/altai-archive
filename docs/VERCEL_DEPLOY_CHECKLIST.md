# Подготовка портала архива к Vercel

Статус: подготовительный документ. Деплой не выполнялся; 2026-11-11 был сделан один read-only AI POST smoke-check Production. Перед дальнейшим запуском устранить перечисленные блокирующие риски; локальный JSON-store и upload не являются production-хранилищем.

## Рекомендуемый демонстрационный режим

1. Подключить существующий репозиторий к Vercel, выбрать Next.js preset и Node.js runtime, не создавать новый проект.
2. Для первого preview использовать синтетические публичные данные. Не загружать `.env.local`, `.data`, персональные материалы, исходные PDF или 7z.
3. Установить в Project → Settings → Environment Variables только нужные переменные. Секреты вводить через защищённую панель Vercel; значения не помещать в Git, build logs, `NEXT_PUBLIC_*` или командную строку.
4. Для демонстрации выставить `DEMO_READ_ONLY=true`. Это блокирует изменение каталога, учётных записей и экспорт/создание резервной копии через app endpoints. Auth session/login/logout остаются техническими операциями и не дают постоянного хранения контента.
5. После появления фактического домена задать `APP_ORIGIN=https://<actual-project-domain>` (только origin, без пути/слеша/параметров) и `NEXT_PUBLIC_SITE_URL=https://<actual-project-domain>`. Не угадывать домен `.vercel.app`; обновить значения для Preview/Production согласно используемым доменам.
6. Для AI использовать только Google Gemini API. В Vercel задать server-only `GEMINI_API_KEY`; модель закреплена в коде как `gemini-3.1-flash-lite`. Google сообщает, что содержание бесплатного уровня может использоваться для улучшения продуктов; не отправлять персональные/закрытые данные и проверить согласование условий обработки с архивом. Точные квоты проекта проверить в AI Studio.

## Переменные окружения Vercel

Значения секретов вводить только в Vercel Environment Variables. Не переносить их в этот файл, Git или `NEXT_PUBLIC_*`. `APP_ORIGIN` и `NEXT_PUBLIC_SITE_URL` должны быть одним и тем же точным HTTPS origin для каждого используемого deployment environment.

| Переменная | Обязательность | Секрет | Назначение |
|---|---|---|---|
| `APP_ORIGIN` | Обязательно | Нет | Доверенный HTTPS origin для Origin/CSRF проверки; без пути и завершающего слеша |
| `NEXT_PUBLIC_SITE_URL` | Обязательно | Нет | Канонический HTTPS origin для metadata, sitemap и robots; должен совпадать с `APP_ORIGIN` |
| `DEMO_READ_ONLY` | Обязательно для публичного демо | Нет | Установить в `true`, чтобы блокировать изменения архивных записей, аккаунтов и экспорт |
| `ARCHIVE_OWNER_EMAIL` | Только если используется админ-вход | Да/конфиденциально | Инициализация владельца; обычному публичному демо можно не задавать, если админка не используется |
| `ARCHIVE_OWNER_PASSWORD` | Только если используется админ-вход | Да | Сильный пароль владельца; вводить только через защищённую панель |
| `SESSION_SECRET` | Для auth endpoints | Да | Случайная строка не короче 32 символов |
| `UPLOAD_LIMIT_MB` | Необязательно | Нет | Лимит загрузки; по умолчанию 25 MB, но постоянное хранилище на Vercel всё равно отсутствует |
| `GEMINI_API_KEY` | Только при разрешённом live AI | Да | Серверный Google AI Studio key; никогда не использовать `NEXT_PUBLIC_`. Model ID fixed in code: `gemini-3.1-flash-lite` |
| `UPSTASH_REDIS_REST_URL` | Обязательно при включённом production AI | Да/endpoint | HTTPS REST endpoint Upstash Redis; приложение закрывает AI при отсутствии |
| `UPSTASH_REDIS_REST_TOKEN` | Обязательно при включённом production AI | Да | Токен Upstash REST; приложение закрывает AI при отсутствии |

`VERCEL`, `NODE_ENV` и `VERCEL_URL` задаются платформой. Приложение не доверяет `VERCEL_URL` вместо явно заданного `APP_ORIGIN`, поскольку Origin-проверка должна знать точный публичный домен. В Production AI endpoint закрывается, если не настроены обе переменные Upstash или доверенный IP Vercel; без `GEMINI_API_KEY` генерации также не будет. Включайте AI только после настройки обеих сторонних переменных и проверки условий Gemini.

## Ограничения текущего приложения на Vercel

- `.data/archive-store.json`, резервные копии, сессии и audit log записываются локально. Файловая система serverless runtime не является постоянным межинстансовым хранилищем; записи могут исчезнуть или быть различными на инстансах.
- Uploads в локальный `.data/uploads` не будут надёжно сохраняться. Не включать публичную редакторскую загрузку/публикацию на Vercel и не представлять админку как полнофункциональную. Для реальной работы нужно отдельно согласовать постоянную БД и объектное хранилище; миграции Supabase без отдельного разрешения запрещены.
- AI имеет общий distributed limiter при настройке Upstash REST: 5 запросов/минуту на IP и 20 запросов/минуту aggregate, плюс локальный concurrency cap. Для production без Redis и надёжного Vercel IP header endpoint закрывается до вызова модели. Перед открытием AI всё равно нужны provider-side hard spending limit и alerts; quotas/free model availability не являются SLA.

## Проверка перед показом

- Установить проверенные origin/site URL. Убедиться, что `APP_ORIGIN` — строгий HTTPS origin без path/query/hash/credentials; URL сайта тоже валиден и совпадает с доменом.
- Проверить production HTTPS, сертификат, канонический URL, `robots.txt`, sitemap и отсутствие preview/private маршрутов в индексе.
- Убедиться, что в client bundle, source maps, HTML, API ответах и logs нет секретов; все `.env*`, `.data`, локальные uploads и исходники комплаенс-архива исключены.
- Проверить `/`, `/catalog`, `/branches`, `/history`, `/assistant`, `/admin` на desktop 1440 px и mobile 390 px, RU/KK/EN, светлую и тёмную темы, keyboard/focus и читаемость.
- Убедиться, что публичный API и AI выдают только `published` + `public`; все приватные/черновые бинарники недоступны без авторизации.
- Отдельно проверить отказ AI при 429/timeout/missing key, лимиты входа/выхода, подтверждённые ссылки и отсутствие платного fallback. Не делать живые платные запросы.
- Проверить, что изменение/перезапуск инстанса не создаёт у жюри ожидания сохранения данных. Демонстрационный контент — синтетический или отдельно проверенный.

## Блокеры перед production

1. Постоянные БД и приватное объектное хранилище для документов/сессий/audit, с резервированием и миграционным планом.
2. Общий распределённый per-IP и aggregate AI limiter, provider hard spend cap, а также согласование privacy/retention и перечня внешне передаваемых полей.
3. Редакторская проверка контактов филиалов и календарных расхождений; утверждение порядка публикации.
4. Ручная проверка прав/персональных данных комплаенс-материалов; до неё файлы и даже перечень метаданных остаются закрытыми.
5. Browser E2E и production-like smoke test в сети, где разрешено слушать локальный порт; затем отдельное разрешение пользователя на деплой.
